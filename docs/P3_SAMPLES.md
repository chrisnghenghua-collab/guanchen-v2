# P3 解读文案｜诊断与样稿（供 Chris 审阅）｜2026-10-22

## 一、诊断：为什么解读读起来模板化
用 500 个随机命盘统计每题的结论分布（脚本逻辑同 `tests\p2_calc_crosscheck.mjs` 的取样方式）：

| 题目 | 结论种类 | 最常见结论的占比 |
|---|---|---|
| 投资风格 | 5 | **90%**（几乎人人「简化与控制风险」） |
| 身心·当前关注 | 5 | **94%** |
| 未来 12 个月财运 | 2 | **80%** |
| 感情·当前关注 | 4 | 65% |
| 财运·机会 | 5 | 59% |
| 事业·现状 | 5 | 55% |
| 其余各题 | 2～5 | 34%～51% |

1. **架构问题**：每题只有 2～5 种固定结论，每种结论配一段固定文字。同一结论下的所有人，读到的文字完全相同。
2. **有几题其实是同一套判断**：身心「日常节奏」「负荷模式」「恢复方式」三题的结论分布完全相同（181/124/109/48/38），只是换了名字；感情三题的结论也高度重合（都是 217）。
3. **底层判断过于集中**：59% 的盘被判为「身强弱均衡」，86% 的盘格局状态为「成格有瑕」或「待确认」。投资风格的第一条规则是「格局待确认或有牵制 → 简化与控制风险」，所以几乎人人都落到这一条。负责强弱与格局判断的模块自标为 `PROTOTYPE_NOT_FINAL`。
4. **「为什么」写的是免责声明，不是理由**，例如「日主强弱只用于理解……不等于……」。
5. **行动建议会重复**，同一句话出现两次。
6. **有自相矛盾的情况**：B 盘「事业现状」的结论是「没有形成明显的高压」，理由却写「当前时运对工作结构形成较明显压力」。
7. **命盘依据只以英文代码出现**（例如 `HURTING_OFFICER_VISIBLE_ENTERED: DAYUN=…`），一般用户看不到，也看不懂。

**引擎其实掌握丰富的命盘事实**：日主与五行、月令旺衰（旺相休囚死）、通根、生扶与克泄、格局类型、透出的十神、冲刑合害，以及大运、流年带来的十神。这些事实在 P2 中已验证计算正确，但目前只用来「选出 5 个结论之一」，没有写进文字。

## 二、建议的新架构
1. **每题的回答固定为 4 段**：
   - **结论**：一句话，明确，落在这个人身上。
   - **命盘依据**：2～4 句白话，点名这个人的实际命盘事实（日主、月令、格局、十神、冲合、当前大运和流年）。专业名词保留，但当场用白话解释。
   - **建议**：2～3 条具体、可执行、不重复的建议。
   - **提醒**：一句话的现实边界。通用免责放在产品说明页，不在每题重复。
2. **文案与判断分开**：做一份「事实句库」，按命盘事实组合成文字，再加上每题的结论模板与建议模板。全部放在一份 Chris 可以直接编辑的中文文案表里。
3. **判断层要重做的部分**（会改变输出，需要另行批准）：结论过度集中的题目（投资风格、身心·当前关注、未来 12 个月财运），以及身心三题、感情三题共用一套判断的问题。
4. **诚实标示**：格局状态为「待确认」时，在命盘依据中写明「格局判断仍有不确定之处」，不把它说成定论。
