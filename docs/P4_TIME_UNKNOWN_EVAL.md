# P4 评估｜不知道出生时辰时怎么处理｜2026-10-22

脚本：`tests\p4_time_unknown_eval.mjs`（150 个随机日期 × 每天所有可能的时辰，经由新接口 v2 实际排盘）。

## 一、关键数据
- 一天通常对应 **13 个候选时辰**（子初换日下，凌晨子时算当天，晚上 23 点后的子时算次日日柱）。91% 的日期，日柱会因为晚子时而有两种可能；年柱、月柱几乎不受影响（150 天里只有 4 天刚好遇上节气交接）。
- 同一天里，换个时辰：身强弱平均有 2 种结果，主导十神平均有 3 种。

**每题「结论不受时辰影响」的比例**（20 题平均）：

| 情况 | 结论稳定的比例 |
|---|---|
| 完全不知道时辰（13 个候选） | **22%** |
| 知道大概时段（例如「上午 6–12 点」，约 3 个候选） | **57%** |
| 缩小到相邻 2 个时辰 | **76%** |

各题差异很大：「换工作」「新机会」「感情·当前关注」这类看大运流年的题目最稳定（完全不知道时辰也有 54%～63%，知道时段可达 84%～91%）；「沟通方式」「界线」「投资风格」「日常节奏」这类看原局性格的题目最不稳定（完全不知道时辰只有 1%～11%）。

## 二、对「问卷反推时辰、给 2 个候选」的评估
1. **理论上限**：13 个时辰平均只能分出约 5 种「性格轮廓」（主导十神 × 身强弱 × 最旺五行）。就算问卷回答完全准确，平均也只能缩小到 2～3 个时辰一组。所以「给 2 个候选」在多数情况下做得到，但不是每次。
2. **循环风险（最重要）**：如果问卷问的是性格（例如「你说话直不直接？」），系统就会挑出一个「让命盘性格符合你回答」的时辰，于是「沟通方式」等性格题的解读，其实只是把你的问卷答案重述一遍，看起来很准，却不是命盘推出来的。偏偏这些性格题正是最依赖时辰的题目。
3. **准确度目前无法验证**：没有真实用户数据，就无法知道问卷猜中的机率。随机猜 2 个、命中正确时辰的机率是 2/13 ≈ 15%；问卷必须明显高于这个数字才有意义。
4. **可以做得诚实的方式**：
   - 优先问**事实线索**，而不是性格：例如「出生时天亮了吗？」「是半夜还是傍晚？」「家人有没有说过大概几点？」这些不会造成循环。
   - 性格问卷先做成**实验功能**：只邀请「知道准确时辰」的用户来做，比对问卷猜中率；猜中率达标后，再正式开放。

## 三、建议方案
**V1（随网站上线）**：时段输入 + 多时辰合盘
1. 先问「知道准确出生时间吗？」→ 不知道时，提示可以找出生证明、医院记录或问家人（多数地区的出生证明或医院记录都有登记时间）。
2. 让用户选**大概时段**（例如：半夜、凌晨、清晨、上午、中午、下午、傍晚、晚上；或「完全不知道」）。
3. 系统把时段内所有可能的时辰都排一次：
   - 结论在这些时辰里**一致**的题目 → 正常显示，并注明「在你可能的时辰里结论一致」。
   - 结论**不一致**的题目 → 写明「这题会因出生时辰而不同」，并列出各种可能，例如「若是卯时（约 5–7 点）：……」，最多 3 种。
   - 年柱、月柱、日柱照常显示；日柱有两种可能时（时段包含 23 点后），两种都列出。
4. 「完全不知道」也可以选：同样按上面的方式显示，只是一致的题目会比较少（约 22%），页面会诚实说明。

**V2（上线后，依数据决定）**：性格问卷反推
- 先以实验功能收集「知道准确时辰」用户的问卷，计算猜中率；达标后才对一般用户开放，结果标示为「推测时辰」，同时显示另一个候选。

## 四、对接口的影响（V1）
- 请求：`birth.time` 为 `null` 时，可加 `birth.timeRange`，例如 `{ "from": "06:00", "to": "12:00" }`，或「完全不知道」。
- 回应：新增「多时辰」模式。`chart` 列出共同的柱和各候选时辰；每题回传 `consistent: true` 加单一结论，或 `consistent: false` 加 `variants[]`（各附时辰标签）。
- 有准确时间时的回应完全不变。

## 六、Chris 的决定与 V1 实际做法（2026-10-22）
- 决定：做问卷反推（V1），反推是概率，不替用户判断 100% 准确；给 2 个候选和百分比，点选后自动填入，再生成正式结果。时段选项：8 个口语时段 + 「我知道大约几点」+ 「完全不知道」。
- 做法：候选时辰的初始可能性 = 该时辰落在时段内的分钟数；8 题各对应命盘的一个特征（主导十神、身强弱、主要五行、日支关系、食伤／财／官杀／印的强弱）；每次只出「还能区分候选」的题，按区分力排序，一般 3 题左右（知道时段）或 7 题（完全不知道）。
- 模拟结果（`tests\p4_estimate_eval.mjs 150`；假设用户的自我描述以一定概率符合命盘）：

| 情况 / 回答符合命盘的比例 | 真实时辰在前 2 名 | 乱猜的前 2 名 | 平均题数 |
|---|---|---|---|
| 知道时段 / 100% | 99% | 77% | 3.2 |
| 知道时段 / 80% | 99% | 77% | 3.2 |
| 知道时段 / 60% | 99% | 77% | 3.2 |
| 完全不知道 / 100% | 90% | 15% | 6.9 |
| 完全不知道 / 80% | 75% | 15% | 6.9 |
| 完全不知道 / 60% | 67% | 15% | 6.9 |

- **诚实说明**：知道时段时，候选本来就只有 2–3 个，所以「前 2 名」的提升主要来自时段本身；问卷真正发挥作用的是「完全不知道」的情况（15% → 67–90%）。以上只验证了模型本身，**真实世界的准确度未验证**（循环风险：用命理特征反推时辰，再用该时辰解读性格）。上线后可请知道准确时辰的用户匿名作答来验证。

## 七、问卷 V2（2026-10-23，Chris 提供并已自测）
- Chris 测试原问卷后认为准确率不高，提供新问卷：12 题（Q1–Q8 心性题，权重 0.4；Q9–Q12 事件题，权重 0.6），每个选项直接对应若干时支。要求：题目、选项与时支对应、计分方式不改，只润色措辞。
- 实作（`engine\api\time-estimate.mjs`）：某时辰得分 = 所选选项包含其时支的题目权重之和；相对可能性 ∝ 时段内分钟数 × e^(0.8 × 得分)（0.8 只决定百分比的集中程度，不改变名次）。依 Chris 的题序发问，只跳过「已答」和「无法区分剩余候选」的题（这类题对所有候选加同样的分，不影响结果）。候选时辰仍由真实历法计算（真太阳时、子初换日）。
- 校验：Chris 的答题样本 C/C/D/C/D/B/D/D/B/D/A/C → 申时第一（63.3%）、巳时第二（9.3%），与 Chris 的测试结果一致（`tests\v2_api.mjs` E-03 固定此结果）。
- 模拟（`tests\p4_estimate_eval.mjs 150`，假设作答以一定比例符合该时支的对应）：完全不知道时辰，真实时辰在前 2 名 99% / 97% / 93%（符合比例 100% / 80% / 60%，乱猜 15%）；知道时段 99% / 99% / 97%（乱猜 76%）。这只验证内部一致性，真实准确度仍需用知道出生时辰的人验证。
- 待 Chris 决定：各时辰能拿到的最高分不同（子 3.2、戌 3.4 … 寅、巳、申 5.2；子时在第 2、4、6、10、11 题没有对应选项），子、戌时较难排到第一。可选改进：得分除以该时辰最高可得分（模拟中 60% 符合时第一名准确率 75% → 82%）。此改动会改变计分方式，未经 Chris 批准不实施。
